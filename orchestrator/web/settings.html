Credential handling

Read-only — there is nothing to configure here. This is what Synagon guarantees.

  • Synagon never reads, stores, or transmits a credential, key, or sign-in artefact of any kind, for any provider.
  • Signing in always opens that provider's own login flow, in its own detached terminal. Synagon starts it and then never waits on it, reads from it, or kills it; whatever you type goes to that provider's CLI.
  • Provider status is read only from commands each provider documents as safe and non-interactive. Synagon never inspects a provider's stored sign-in state directly.
  • Every provider CLI's output is passed through one redaction filter before it is shown or written anywhere — key-shaped, bearer-token-shaped, and secret-shaped text is replaced, not truncated.
  • Subscription and entitlement are only ever reported when a provider itself states them. Synagon never infers or claims a plan or tier.
